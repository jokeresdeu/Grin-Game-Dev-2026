# Звіт по лабораторних роботах №4 та №5

## Лабораторна робота №4 - Анімації в Unity

**Мета:**  
Додати анімації для гравця та об’єктів сцени, керуючи станами через код.

### Реалізація

У межах лабораторної роботи було проанімовано як самого персонажа, так і частину інтерактивних об’єктів рівня.

### Проанімував мінімум 5 обʼєктів

#### Гравець
Для гравця реалізовано такі анімації:

- `Idle`
- `Run`
- `Jump`
- `Attack`
- `Roll`
- `Hurt`
- `Death`
- `Block` *(візуальна анімація без окремої бойової логіки)*

#### Вороги
Для ворогів реалізовано:

- `Idle`
- `Attack`
- `Death`

#### Інтерактивні об’єкти та середовище
Було додано анімації для:

- ключа при підборі
- шипів / небезпечних пасток
- декоративних об’єктів сцени
- меню та UI-елементів

### Керування анімаціями через код

Керування анімаціями реалізовано за допомогою компонента `Animator` та параметрів стану.

Зокрема:

- перемикання між `Idle` і `Run` залежно від руху
- запуск `Jump` при стрибку
- запуск серії `Attack` при атаці
- запуск `Roll` при перекаті
- запуск `Hurt` при отриманні шкоди
- запуск `Death` при смерті
- активація допоміжних станів (`Grounded`, `WallSlide`, `AirSpeedY`, `AnimState`) для синхронізації руху та анімації

### Результат

Завдяки анімаціям гравець та об’єкти сцени стали візуально зрозумілішими, а ігровий процес — більш живим і читабельним.  
Стан персонажа тепер добре відображається не лише через механіку, а й через візуальну реакцію.

## Лабораторна робота №5 - UI

**Мета:**  
Створити ігровий UI для індикації стану гравця та управління грою.

### Реалізація

У межах лабораторної було додано базові елементи інтерфейсу для взаємодії гравця з грою та відображення поточного стану персонажа.

### Додані UI елементи

- **Індикатор здоров’я (HP)**  
  Реалізований через `Image.fillAmount`, оновлюється при отриманні шкоди або лікуванні.

- **Індикатор досвіду (EXP)**  
  Також реалізований через `Image.fillAmount`, оновлюється при отриманні досвіду.

- **Відображення рівня гравця**  
  Реалізовано через `TMP_Text`.

- **Лічильник ключів**  
  Додано UI-елемент, який показує:
  - скільки ключів уже зібрано
  - скільки ключів потрібно для відкриття дверей

- **Меню смерті**
  - відображається після смерті персонажа
  - містить кнопку перезапуску сцени

- **Головне меню**
  - стартова сцена гри
  - можливість запуску гри

### Реалізовані класи для керування UI

Для оновлення UI створено та використано окремі скрипти, зокрема:

- `PlayerView`
  - оновлює HP
  - оновлює EXP
  - оновлює рівень

- `KeysUI`
  - відображає кількість зібраних ключів
  - показує необхідну кількість ключів для відкриття дверей

### Взаємозв’язок UI з ігровою логікою

Інтерфейс синхронізований із поточним станом гри:

- при втраті HP оновлюється смуга здоров’я
- при отриманні досвіду оновлюється EXP bar
- при підборі ключів змінюється лічильник ключів
- при смерті відкривається меню програшу

### Результат

Завдяки UI гравець постійно отримує зворотний зв’язок про свій стан, прогрес та умови проходження рівня.  
Це покращує зручність гри та робить ігровий процес зрозумілішим.

## Висновок

У межах лабораторних робіт №4 та №5 було реалізовано повноцінне розширення прототипу гри **Classic Platformer**.

Було додано:

- базові механіки взаємодії
- бойову систему
- систему здоров’я та досвіду
- ворогів і пастки
- систему ключів, дверей і переходу між сценами
- анімації персонажа, ворогів і об’єктів
- інтерфейс користувача для відображення стану гри

У результаті прототип став значно більш цілісним, інтерактивним і наближеним до завершеної 2D-гри.

**Додаткові завдання на бонусні бали не виконувалися.**
