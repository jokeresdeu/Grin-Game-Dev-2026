# Chicken Hunt — Звіт виконання завдання (Interaction)

---

# 1. Обрана гра

Зі списку проєктів було обрано гру:

## Chicken Hunt (звичайний рівень)

**Опис гри:**
Гравець керує зброєю та знищує курок, що рухаються по сцені. Мета — набрати необхідну кількість очок, уникаючи втечі курок за межі карти.

---

# 2. Нові механіки взаємодії

У проєкт було додано мінімум 3 нові механіки взаємодії:

---

## 1. Додатковий ворог (Score System)

* має більший розмір і більшу кількість hp
* має додаткові елементи дизайну та мемну мелодію при спавні)

---

## 2. Умова програшу (Lose Condition)

* Якщо певна кількість курок покидає межі карти
* Гравець програє

**Логіка:**

* перевірка позиції курки (`transform.position.magnitude`)
* лічильник `_escapedChickens`
* поріг `_maxEscapedChickens`

---

## 3. Умова перемоги (Win Condition)

* Гравець перемагає при досягненні певної кількості очок (наприклад 2000)

**Логіка:**

* `_score >= _winScore`
* виклик `EndGame(true)`

---

## 4. Перезапуск сцени

* Після win або lose гравець може перезапустити гру

**Реалізація:**

* `SceneManager.LoadScene(SceneManager.GetActiveScene().buildIndex)`
* кнопка UI викликає `RestartGame()`

---

## Додатково використано UI елементи:

* **TextMeshProUGUI** — рахунок
* **GameObject Panels** — Win / Lose екрани
* (можливо розширення: Slider / Image для HP або прогресу)

---

# 3. Система станів гри

## 🎮 Основні стани:

* **Playing** — активний геймплей
* **Win** — гравець переміг
* **Lose** — гравець програв

---

## 1. Типи колізій, що використані

### Physics2D колізії:

* `Collider2D` у курок
* `RaycastHit2D` у зброї

### Використання:

* Виявлення попадання по курці через raycast
* Перевірка меж карти (distance-based check)

---

## 2. Де використано Raycast / Overlap

### Raycast використовується у Weapon:

* `Physics2D.Raycast(mouseWorld, Vector2.zero)`
* Визначає, чи попав гравець у курку

### Overlap не використовується (можливе розширення)

---

## 3. Чому обрано цей метод

### Причини використання Raycast:

* швидка перевірка попадання
* не потребує складної фізики
* підходить для аркадної стрільби
* мінімізує навантаження (краще ніж фізичні снаряди)

---

## Альтернатива (чому не Overlap)

* Overlap потребує радіуса
* менш точний для стрільби мишкою
* складніше контролювати приціл

---

## 4. Як механіки впливають на core loop

### Core Loop гри:

1. Курки спавняться
2. Рухаються по сцені
3. Гравець стріляє
4. Отримує очки
5. Частина курок тікає
6. Гравець або:

   * набирає 2000 очок → WIN
   * пропускає 5 курок → LOSE

---

### Вплив механік:

* **Score system** → дає мету гри
* **Escape system** → створює тиск на гравця
* **Win/Lose system** → завершує цикл
* **Restart system** → дозволяє повторний цикл

---

* стрільбою через raycast
